# D / T19 原文与语音草案联调

这是本机集成候选，基于main@3a22a02、A的T13@5cf6d0d、C的T16@d38bfe7和D的T15@c0116c9。T13/T16仍未合并，不能把本分支直接推入旧T15 PR或作为组员已批准的版本。

目前可做：直接粘贴一段原文，或由用户手动录音后核对转写；人工发送到既有T12提取接口；修改任务、截止精度、材料和可选字段；保留修改继续整理；取消、停止播报和切后台释放。首次来源信息默认折叠，不要求用户预填任务字段。原文、草案和配置仅在本次页面/进程内，不把它们说成正式历史已保存。

**当前没有正式保存。**T13原保存器没有T16持久确认/幂等协议；T16目前没有新建材料清单的提交字段。新联调页禁用保存，并使用只读NoticeCommitGate，即使代码直接调用确认也返回COMMIT_UNAVAILABLE，不回退到基础create或分别写材料。生产T13页面的原保存路径未被此探测页替换。

## 导出与检查

在当前集成分支的干净client源码上，使用已有DevEco编译器运行：

```text
node scripts/test-notice-interaction.cjs
node scripts/prepare-notice-chat.cjs <全新英文路径>
```

编译器沿用现有DEVECO_CLI_STUDIO_PATH/T08_TYPESCRIPT_PATH。导出复用T15白名单/签名清空机制；新包名com.campusddl.noticeprobe，版本0.1.0/100，权限只有MICROPHONE/INTERNET。T13页面在导出时装配语音，不将Harmony原生Kit写进共享生产装配。原T15和业务应用包名不变。

启动入口仍为语音对话页：先在“设置”自行填写团队网关和项目凭证，再点“通知草案联调”。该页调用/api/agent/extract-notice，原对话页仍调用/api/model/turn。服务商Key仅服务端；本机T15旧合成服务不包含通知提取端点，不能把其回复当提取成功。

录音、发送和播报均由用户主动点击，不自动读剪贴板或聊天。语音发言读完立即结束；新原文会清除上一份草案的回答覆盖。日期只知某一天时不补23:59。播报前缀说明尚未保存，停止不会删除原文或草案。

## 检查边界

主机检查使用实际T13控制器和T09语音控制器，模型/原生端口模拟。它们证明请求、编辑、取消和阻止不完整保存的行为，不证明模型理解准确、真实麦克风/声音或提醒到达。SDK构建、设备和模型状态以[本轮集成记录](../../docs/setup/T19-notice-interaction-validation.md)为准。

尚待：T16材料创建/编辑的一致提交及其回执、T17完整工具/上下文、多任务拆分、正式共享owner/页面接入、草案跨进程恢复与系统提醒。需要C/A/B补齐的字段和流程见[提交接口缺口](../../docs/setup/T19-material-commit-handoff.md)。
