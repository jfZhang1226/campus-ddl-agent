# A/B/D：UI 与语音接口草案

日期：2026-10-27。提出者：D。**状态：待 A/B 评审，未冻结、未接入原生 API。** 沿用现行总纲第 10 节的 SpeechAdapter 职责，不更换团队网关或业务确认协议。

## 1. 已知依据与待定项

- 用户设备照片：Pura 70 / HarmonyOS 7.0.0.109 / API 26；照片不证明录音、ASR 或 TTS 可用。
- 共同工程以 ArkUI-X 共享页面为基础；平台语音能力隔离到适配层。
- B 的网关现有模型接口为 `POST /api/model/turn`；本轮 PR #7 修正已通过 D 复查。ASR/TTS 接口、原生服务开放条件、录音格式/采样率及 SDK 签名仍需 T09 实测。
- 这里的类型/事件名是协作草案，不是已存在的客户端方法，也不是对华为 API 的签名转录。真正实现时由 A/B/D 一次性对齐。

## 2. 模块分界与调用链

1. D 的语音组件向平台适配请求录音/识别，显示状态；识别结果交给 A 的可编辑输入框。
2. 用户核对后点击发送；A 的统一文本入口把文字交给 B 的共用 Agent。语音与粘贴走同一业务入口，不在 D 的适配器里直接创建任务。
3. B 返回回答/追问/工具请求，由共用 Agent 校验和推进。D 展示状态或配合卡片交互；正式任务写入仅由客户端屏幕确认事件触发，并等待 C 的真实提交结果。
4. TTS 只播报经确认的简短显示结果。草案只能说“已整理，待确认”；正式保存失败不能播报“已创建”。播报失败不撤销已保存任务。

## 3. SpeechAdapter 建议职责

| 方法 | 建议输入/输出 | 必须约定的行为 |
| --- | --- | --- |
| capability | 返回录音/ASR/TTS/停止能力及不可用原因 | 只返回已探测能力；其他端未实现则明确不可用 |
| startRecording | 当前输入代次；异步成功/权限或设备错误 | 禁止并发开两次录音；权限拒绝不改任务状态 |
| stopRecording | 返回本地音频引用、实际格式、实际时长 | 不在会话/日志写入录音内容或真实路径；格式由探测确定 |
| recognize | 音频引用和当前输入代次；返回转写文本 | 识别为空返回明确结果；成功后先供用户编辑，不自动发送/确认 |
| speak | 经界面认可的短摘要及播放代次 | 不替模型或 Repository 宣布成功；启动播放可取消 |
| stopSpeaking | 当前播放代次；可重复调用 | 停止必须影响实际播放器，不只清除页面动画 |
| cancel | 当前输入/播放代次 | 停止相关录音/识别/播放；迟到回调不能恢复已取消状态 |

音频引用是应用私有的临时资源句柄，具体结构和清理策略待 T09 决定；不把任意文件路径交给模型。30 秒只作为总纲的初始单次录音建议上限，实际格式、上限和可用性以选定路径验证为准。

## 4. UI 事件草案

| 事件 | 归属及处理 |
| --- | --- |
| 转写就绪 | D → A：提供文字和当前输入代次；输入框允许编辑 |
| 用户发送文字 | A → 共用 Agent：只提交一次用户核对后的当前文字；不是麦克风结束即自动发送 |
| 处理状态变化 | B/Agent → A/D：理解通知、查询任务、待补充、待确认；不把所有阶段合并为“已完成” |
| 用户确认/取消卡片 | A/D → 现有确认流程：绑定当前方案与版本，实际提交由 B/C 对接；D 不新增模型可调用写入方法 |
| 实际提交结果 | C/业务层 → A/D：成功才展示已保存；失败保留草案；冲突重新读取并确认 |
| 播报停止 | D → 实际播放器：中止音频；既有业务结果保持 |

请求所有者应由 A/B 共同确定。客户端保存本地输入代次，在重录、更改原文、切换会话、离页/后台取消时作废旧代次；服务器返回的 requestId 用于关联诊断，不能因为晚返回就覆盖较新输入。不同客户端代次字段不擅自加入网关已接受的请求协议。

## 5. 语音状态与业务状态分开

语音状态沿用 `idle / recording / recognizing / ready / speaking / error`；取消完成回到 idle，保留已编辑文字。业务状态由共用 Agent 管理，至少表达处理中、待补充、待确认、保存中、成功、失败。

| 触发 | 语音反馈 | 业务/输入保持 |
| --- | --- | --- |
| 拒绝麦克风权限 | 提示无法录音及恢复入口，允许文字输入 | 不清空输入，不改变任务 |
| 识别失败或空文本 | 重录或编辑入口 | 不显示“任务已创建” |
| 用户更改转写 | ready，等待点击发送 | 使用编辑后的文字，原始通知不被悄悄改写 |
| 取消后识别结果晚到 | 丢弃旧结果 | 不替换新输入 |
| 模型/网络失败 | 显示具体原因和重试 | 保留文字和当前草案 |
| 保存失败/版本冲突 | 展示真实失败/重新确认 | 不增任务，不播报已保存 |
| TTS 失败或被停止 | 显示结果仍可阅读，可重播 | 不回滚已成功的业务操作 |
| 离页/切后台 | 明确取消录音和播放，作废相关代次 | 不自动提交草案；正式提交若已经发起，应查询实际结果而非假设回滚 |

## 6. 网关错误到界面

现有项目网关错误码：UNAUTHORIZED、RATE_LIMITED、INVALID_REQUEST、CONFIG_ERROR、MODEL_ERROR。分别提示访问凭证问题、稍后重试、请求不符合约定、服务配置问题、模型服务未完成请求。用户输入与草案都应保留。

客户端连接失败/超时由 A 的网络层分类；不要声称网关当前已经返回独立的 NETWORK_TIMEOUT 等新错误码。UI 不展示服务商密钥、原始异常堆栈或完整通知日志。项目网关凭证与服务商 API Key 分开；服务商密钥留在 B 的服务端配置。
