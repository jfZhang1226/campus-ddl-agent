主责成员负责推进任务、形成交付物并提交验证记录。协作成员负责约定的接口、材料或评审，任务交付由相关成员共同检查。任务数量用于覆盖核对，实际工作量以模块难度与联调情况为准。

## 2. A：跨端工程与客户端

### 2.1 职责定位

A 负责把共享工程、模型、数据与语音能力集成为可操作的客户端，并保证鸿蒙与 Android 来自同一套核心业务和 UI 代码。A 维护页面整体接入与两端构建，D 配合交互与语音组件，B、C 提供各自模块接口。

## 8. 开展与验收方式

1. 从个人主责任务和共同任务中，选择依赖已具备的工作建立 Issue，保留总纲任务编号。
2. 任务较大时拆分子任务，每项注明负责人、配合对象、交付内容和验证方式。
3. 独立资料、工程、网关、数据和语音探测可按依赖并行推进；正式集成前先对齐接口。
4. 交付时提交源码或材料、实际验证记录、关联 PR 和未解决问题，由另一名相关成员评审。
5. 同一主分支提交版本进行两端联调；模拟数据用于独立开发时明确标注，真实调用和最终验收使用实际能力。
6. 按总纲的基础能力、核心业务、交付候选、最终交付完成条件核对进展。

P0、P1、P2 的范围与先后关系沿用总纲。T31 中的轻量动效按 P1 完善，Android 语音等 P2 能力按实际需求另行确认。通知 DDL、七日排程等属于应用功能，不是成员的开发期限。
