# T19：停止模型整理，保留当前内容

2026-11-16，D 的交互增量，沿用当前通知提取和确认保存协议。

## 行为

提取中页面此前只有等待提示；草案区取消会清掉草案，用户只能等待或退出页面。新增固定页头“停止整理”按钮，仅在extracting可见，不受编辑区禁用影响。

- `stopExtraction()` 只处理extracting：先使当前响应代次失效、调用现有transport取消，再回idle，复用CANCELLED提示。保留原文、模型原draft、字段修改、材料及人工来源、缺项、版本；用户可手动重试，也可核对保留下来的草案后明确确认。
- 不重发请求、不播报、不写正式任务或pending。重复停止不增加取消调用，旧成功/失败不能改变停止状态或新请求。
- 它不同于“取消草案”，不清空草案；不取消保存、锁定方案、语音或已完成结果。释放后的语音组合忽略停止请求。
- 不修改schema、网关或C提交算法，也不承诺客户端取消必然中止服务商计算/计费。

## 验证要求

新增4项交互检查覆盖首次/续次停止、手动重试、迟到成功与失败、语音及dispose；新增2项真实主机文件检查覆盖停止前后快照字节不变、保留编辑可确认，以及保存中/失败pending/终态不被取消。导出检查同时核对共享和原生页头入口，不只测试纯控制器。

设备使用独立验证包与明确的本机合成慢响应服务，不接真实模型；停止、重新发送及后台释放分别记录。可控响应和真实模型证据分开，不将其算为模型理解能力验收。
