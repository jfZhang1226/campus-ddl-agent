# 当前事项完成判定与弹窗修改（2026-11-25）

用户要求：全部事项完成的任务移出待办；追加未完成事项后回到待办；修改使用弹窗。

## 已决定的行为

- 列表完成情况由同一持久化快照中的当前清单计算。非空清单全部 `prepared` 进入“已完成”；存在 `pending` 进入“待办”。暂存、勾选但尚未确认的修改不影响分类。
- 空清单不推断完成，沿用明确的 `done` / `submitted`；取消任务仅在全部中显示为已取消。七天内与待补日期均不包含已完成或取消任务。
- 这是清单工作进度，不代表学校平台收到提交。不改写正式状态、提交声明、历史回执、计划或提醒策略。提交历史仍可单独核对。
- `TaskList.progress` 为同快照只读统计，不是新增存储字段或模型写入参数；不增加逐任务读取。
- 对先前明确 `done` 的任务，仅当本次明确追加新事项、没有改写旧事项、目标为 `in_progress`、剩余工时恢复未知且没有提交声明时，允许通过原 C 确认链重新开始。阶段与应用阶段均校验。此条窄化替代旧决策中 done 一律禁止追加的规则；取消保护、提交终态和历史不变。
- 修改预览使用居中系统自定义弹窗，保留页面背景和固定确认/取消按钮。返回键只收起预览，待确认方案保留并可重新打开；取消才撤销方案。保存中不允许退出；失败和不确定结果仍可恢复读取。
- 任务和对话草案的截止编辑也用弹窗，非法输入在原弹窗纠正；取消不改变正式任务。仍保留“编辑→方案核对→客户端确认”的流程。

## 验证边界

主机确定性测试覆盖清单完成、新增、取消勾选、空清单、隔离、提交历史、已完成追加和终态保护。SDK 与真实手机结果单独记入 status；未完成前不声称已更新手机。
