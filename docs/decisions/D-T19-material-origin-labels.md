# T19 确认前显示材料来源

2026-11-16，D 的确认卡交互补充，沿用现有字段和客户端确认流程。

## 问题与行为

此前材料只有保存回读时显示来源；`setMaterial` 改写模型材料后仍保留 `materialFromNotice=true`，可把用户替换的内容归为原通知要求。已用确定性回归复现，新增四例中三例在修复前失败。

- 确认卡逐项显示“通知提取 · 待核对”或“人工补充或修改”；通知提取是模型的提取来源，不保证逐字引用或模型正确，原文继续完整展示供核对。
- 编辑后的去首尾空白文本与当前值不同时，将该项现有标记置为 false。相同内容或仅首尾空白不改变归属，提交仍按既有规则去首尾空白。
- 改回原内容也不自动恢复通知归属；缺少稳定的逐项证据映射时保守保留人工标记。删除、空项过滤、继续整理及待确认方案恢复沿用原数组对齐规则。
- 保存沿用原有 `false → sourceNoticeId=null`，不改 DTO 结构、网关协议、存储 schema 或 C 的提交算法。通知原文、完整来源、待准备状态、用户确认权限保持既有约束。
- 回读人工项同样显示“人工补充或修改”，避免把人工改写误称为新增；删除全部材料后不再声称原通知没有列出材料。

## 验证边界

新增回归覆盖正式快照/操作回执/回读来源、空白与同值、改回原值/删除/过滤/模型再整理，以及失败保存后冷恢复/锁定/确认/冷回读。原 T13 基础导入回归同步核对改写项来源，不保留错误的“所有项都来自通知”断言。
