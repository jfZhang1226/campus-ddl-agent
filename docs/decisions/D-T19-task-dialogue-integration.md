## 当前实施

- 新任务助手页从共享Index进入；原通知导入/语音探测入口保留。任务对话使用同一应用ClientStorage，查询由真实TaskRepository/LocalStore执行。
- B循环支持查询、回答/澄清和propose，8步上限；D增加有界网关编解码、取消/后台/90秒网络等待预算和来源/确认适配。模型工具白名单仍不包含confirm/apply/cancel。
- 每条用户输入先写入C会话仓库，属于`session-taskagent-`命名空间；新对话归档旧会话，不删除历史。模型接收必要的最近对话与单独原文，用户补充不拼写或覆盖首通知。
- 可信Notice由已保存用户消息派生稳定ID/原文/SHA-256和真实消息创建时间，publishedAt保持未知。模型notices必须为空，所引用来源必须属于已准备输入或正式记录；客户端只附上实际引用的新Notice，模型不能伪造导入时间/hash/来源事实。
- 第一条消息可仅贴通知；缺项可澄清，后续直接自然语言补充。已有未确认方案时，发送框明确说明发送补充会取消旧未保存方案并重新整理；取消由实际用户发送动作触发，旧方案以终态保留，旧字段/材料作为priorProposal传入，不自动正式写入。
- 待确认卡显示真实方案的任务、旧/新截止、材料、原文与日期精度，点屏幕按钮才经C确认/apply。保留原request失败重试；阶段结果不确定时先只读恢复，不生成隐藏重复方案。会话与业务分文件，失败分别提示，不冒充跨文件事务。
- 查询结果最多展示给模型30任务并明确total/truncated，请求/响应有尺寸上限；截断时要求收窄条件，不以部分结果冒充全部。
