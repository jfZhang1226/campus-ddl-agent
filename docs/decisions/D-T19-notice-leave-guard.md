# D/T19：未保存通知的离页确认

2026-11-16。用户在声音测试中误点退出，当前页面直接释放未保存原文/草案，只能由开发记录重新填入并再请求模型。本次在共享NoticeImport和其原生语音装配中增加同一离页保护，改善这个已发生的问题；不新增自动草稿持久化或聊天/网关协议。

- 页面“返回”、系统返回手势、保存成功后的返回入口复用NoticeLeaveGuard。空页面和已正式保存的页面可以直接返回；保存/恢复等提交协调忙碌期间阻止离开。
- 有原文、来源元数据、草案或未完成语音时先展示确认。继续编辑只关闭提示，现有原文/编辑/材料来源保留，不重发模型。请求中的模型回复可继续更新当前草案；明确放弃离开才调用既有pause使迟到结果失效。
- 打开提示时停止语音，保留已有文字和草案，避免录音/播报在确认界面继续。未完成的录音不会凭空变成转写。
- 有pending或未知暂存结果时显示“保存结果仍需核对”，返回保留本地已有记录，不自动确认或cancelPending，不承诺未知记录已经可靠落盘。冷恢复继续走既有确认规则。
- 提示期间若迟到恢复改变锁定状态，旧的放弃同意不能沿用为另一类状态的同意，先刷新提示再要求明确选择。重复返回不会绕过已打开提示；提交中不能通过放弃绕过保护。
- Guard只返回导航决定，没有router、存储、业务确认或取消权限。页面控制路由与现有生命周期，原文不拼入其他消息、不写入新文件，不改T12/T16或业务schema。

新增8项确定性导航/实际控制器/主机文件检查，连同原37项保存与恢复共45项通过；交互19、T13通知19及相关严格TS通过。模型与语音用注入端口，SDK和手机返回动作另行核对。不能将“返回前提醒”表述为强停/卸载后未确认草稿也可自动恢复。

验证导出身份仍为独立noticeentry和noticeprobe，分别升300/400，增加Guard源码指纹。已有200包恢复矩阵和300语音包声音证据保留其原提交范围，不自动扩展为新包完整验收。
