# D/T19：通知保存恢复的隔离设备验证

语音与普通通知保存已有有限设备证据，但设备外部调试目录读取被平台拒绝，不能用页面成功字样冒充快照/幂等检查。本次沿已有CommitCheck开发验证页，增加应用自己读取合成快照的T19诊断面板，不改业务确认核心、模型协议、存储schema或业务数据恢复策略。

## 验证边界

- 每次新场景由页面分配`campus-ddl-t19-recovery-时间戳`全新应用私有目录；索引也独立。诊断逻辑拒绝已有主文件、恢复痕迹或报告，不覆盖旧测试或正式任务。
- 使用同一NoticeConfirmedWriter、NoticeSaveController、LocalStore、CommitServices；不导入应用getClientStorage、不请求模型或语音、不接收任意路径/原文。通知、两材料、日期与人工来源均固定合成。
- 一次主快照替换使用不存在源文件，经过真正FilePort触发文件API错误，保留原主文件。另两场景在真正替换成功后受控抛错，模拟调用方未收到应答，不能称随机故障、物理断电或网络断线。
- 覆盖保存失败后的只读恢复/重新确认、同实例原操作重试、暂存应答丢失、已提交结果识别、独立版本变化后冲突/取消。比较实际业务快照字节、预留ID、来源、回执和实体数量。
- 读取/恢复按钮不授权或执行；待确认方案仍需明确屏幕确认。提交/取消终态保护。仅诊断按钮明确授权的人工测试数据可写入隔离目录。
- 诊断报告是独立测试记录，不是另一份业务存储或确认授权。报告缺失/损坏或主文件与记录不符时拒绝操作，保留文件；没有自动清理、自动修复或提权。

## 交付方式

正式通知/语音页面逻辑不变。共享入口验证导出保持独立包`com.campusddl.noticeentry`，本次版本升到200；只为保留数据更新验证包，不改团队业务包版本。导出将开发页和诊断源码加入指纹清单，仍为空签名/仅INTERNET。原noticeprobe/300的已有声音证据不扩大到新诊断页。

新增9项实际主机文件检查与原28项确认保存检查通过，相关严格TS通过；设备UI、真实文件API和真正进程重启仍需SDK构建/签名安装后独立执行。此前主机/模型/声音结果保持各自来源。五种受控场景不代表完整失败矩阵，首次存储损坏后的T30恢复、任意断电/系统中断仍未完成。
