# 鸿蒙最小版本的无声收尾

2026-11-17，用户要求建立持续goal，将无需本人出声的剩余工作继续完成。以已合并PR17的main/0a6b283为基线，新分支codex/d-silent-mvp-completion；不继续更新已合并PR17。当前只查到T13/T17旧开放PR，尚无已提交T22/T25或提醒模块，不能声称已有可接入接口。

## 实施顺序

1. 真实任务列表和详情，作为后续提醒、材料和安排操作的入口。直接使用唯一ClientStorage.tasks，原文/材料由实际TaskDetail读取；日期未知保留未知，date_only当天不按午夜判逾期，exact按瞬间判断。列表按北京时间分组，仅为截止列表，不称工作排程。
2. 鸿蒙ReminderAdapter与用户明确启用/取消入口，平台端口隔离；缺具体时刻不擅自生成精确到期提醒。默认不开启，拒绝权限保留任务主流程。记录已注册提醒并对齐任务版本、改期和终态，不能仅以调用成功假定实际收到提醒。
3. 材料/提交状态与安排功能沿用现有模型、确认和快照规则，先审阅C预留集合和协议，再做必要兼容扩展；不另建影子业务库或重复实现网关。
4. 多任务/歧义与恢复、演示材料、可独立执行的无声实机验证。真实用户访谈/试用、个人授权、听觉/录音验收独立留待，不伪造结果。

## 无声约束

当前不启动麦克风、TTS或有声提醒。提醒API的ringDuration=0仍可能使用系统通知音，不能把0当静音；平台静音能力未实际核实前，不执行临近触发试验。可先验证未来提醒的注册/读取/取消，或在通知通道验证后使用静音通知。平台权限和账号授权由本人处理，等待期间继续不依赖它们的工作。

参考：华为当前ReminderAgent API与本机API26类型定义，https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-reminderagentmanager/ 。SDK/模拟/真实模型/真机/本人听觉证据始终区分。

## 提醒登记与恢复的实施约定

新增ReminderPlan/Settings/Service及TaskReminderController，偏好和OS登记意图用同一个StorageCoordinator下reminder-settings.json的版本快照/备份保存；它只存提醒设置，任务仍从唯一TaskRepository读取，没有复制业务数据库。先写pending意图再调用OS；稳定key由任务ID/版本/实际DDL/提前量产生，重启先查真实系统登记，处理OS成功但回执/文件失败，不重复发布。取消先持久化意图，再清理仅匹配本模块key的系统记录，核对后才显示取消完成。

已登记但系统侧消失的提醒不自动复活；未知时间、已过提醒点、任务删除/终态撤销提醒，改期清理旧key后再登记新时刻，实际登记后再复查任务版本。提醒计划始终单独核对/屏幕确认，模型无此能力；默认不启用，拒绝通知不妨碍任务保存。设置损坏保留原文、不静默重置。

LocalStore新增提交成功后的只读订阅，用于ReminderOwner对齐已启用提醒；通知不能改变业务回执或延迟存储队列，失败不把业务成功说成失败，提醒设置写入不会再次触发业务订阅。应用启动/前台复核已存意图，退出不主动删除用户已启用的系统提醒；仅个人明确取消或业务变化触发清理。

平台桥只在原生导出注入，增加PUBLISH_AGENT_REMINDER，使用API26 fixed timezone日历提醒与getAllValidReminders确认实际编号，非本模块的提醒不取消；notificationId碰撞拒绝覆盖。ringDuration=0依然可能使用系统提示音，因此本阶段不安排临近触发，只可测试远期登记/读取/取消，不宣称静音送达或已实际响铃。当前20项确定性/严格TS通过，含页面预览不发布、确认后发起、权限拒绝、版本冲突/销毁、提交观察者错误不污染回执；尚未完成本增量SDK/设备/权限/真实系统提醒验证。

## 下一阶段：材料状态和用户提交历史（协议实施前约定）

不在TaskBoard直接调用基础CRUD改材料。扩展原T16确认引擎的可选材料状态草案与v3 tag，旧v1/v2继续读，新tag让旧客户端拒绝未知协议；方案、业务材料/任务版本、操作回执仍在同一快照提交。材料前状态存入方案，正式prepared时间来自实际确认/提交时钟；重复/冷重放返回原回执，不重写确认时间。模型白名单暂不增加材料写入或提交确认能力。

任务终态不可因新截止/要求回退；准备完成须所有当前材料已准备，已提交须从已准备并经屏幕明确确认。普通无提交要求的待办可工作完成；有提交要求的任务不以done冒充提交。用户声明仍不代表平台收到。提交时的材料/来源/渠道快照随正式操作回执保留，后续变化只提示重新核对，不抹去历史；需要明确重新确认时记录新的用户声明。

当前刚新增TaskStateRules及可选DTO类型，尚未接入v3编解码/提交/UI/测试，不称材料状态已完成。材料删除/来源绑定的历史兼容与旧v2创建材料引用规则需另验证，不擅自删除导致历史回执校验失败。

## 同名任务选择和新增要求

TaskAgentController展示get_tasks的实际候选，屏幕选择再读取实际详情/来源，把ID与版本作为本轮选择约束；选择不联网、不自动发送、不修改任务。多候选查询后不能直接猜测更新其中一项，用户选择后更新不能转移到其他ID或版本。当前只支持选择单一既有目标，批量同名更新需分次核对；不同任务的新建仍可在一个方案原子提交。重启不自动恢复选择权，待确认方案仍按原确认协议恢复。

## 手动剩余工时与时钟保护

任务详情新增剩余分钟输入，空表示未知，0不自动完成；仍走同一待确认方案，旧新工时在卡片明确展示。未整理的材料名称或工时会阻止其他动作把它们悄悄丢掉，离开/刷新须先处理；正式保存后重新读取实际详情，避免把成功保存误报成放弃勾选。28项材料/人工控制器检查及原92项主机提交回归通过。
