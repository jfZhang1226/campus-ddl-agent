# 七日工作安排的有限实施约定

2026-11-17，承接用户无声收尾goal。根目录早期v0.3把完整排程列为P1，共同仓库后续统一总纲把进度重排列为核心闭环；此处记录差异，不把旧截止列表冒充排程。先完成纯规则候选与不变量检查，再接同一C确认/快照机制和页面，不另建影子任务库。纯规则通过不代表安排已持久化或T24—T27已完成。

输入为唯一仓库读出的任务/版本、用户明确提供的剩余分钟、带偏移的可用区间、既有工作块、当前时刻和不超过七天的范围。材料已准备不等于工作耗时为零；剩余工时由用户确认，不由模型猜。输入范围之外的既有块保留，跨范围边界、locked及done块不被重排。remainingMinutes表示当前尚需工作，已完成块不再次从中扣减；仍未完成的保留块会占用同一份剩余工作，避免重复排量。

仅对精确DDL生成能校验的截止前候选，date_only/unknown明确列出需补时刻，不补23:59。合并可用区间的并集，扣除不可移动块，按精确截止、用户优先级、稳定ID排序，按最多30分钟拆分到空闲区间。分钟网格向前起点取整、截止向下取整，不越过精确时刻；工时不足或截止前容量不足返回未安排分钟与原因。启发式未找到不代表全局无解，容量足够也不代表所有截止约束可满足。

不可移动块重叠、超出可用区间或不满足当前DDL/剩余工时等冲突保留原块并明确返回，阻止新安排掩盖问题。零工时不自动完成任务；新候选不修改任务DDL、工时或状态，不触发系统提醒。候选使用输入revision和任务版本形成稳定ID，重试可比较，不能随机创建重复块。

持久化计划将继续使用BusinessSnapshot.availabilityBlocks/planBlocks与原方案/回执的版本tag扩展，先记录协议与兼容，再接明确屏幕确认、全局revision和相关任务version复核；旧保留对象不得静默抛弃。当前本文为实施约定，未声称保存协议/页面/真实模型排程工具已接通。

首轮WeekPlanner纯规则已实现，14项主机检查/strictTS通过，含80组确定性工作量的无重叠/不超可用区间/不越DDL/不重复工时检查。未来范围外的保留块仍计入同一任务剩余工作，但不因未提供范围外空闲时间而制造冲突；已完成块不再扣剩余量。此处没有网络、OS或正式保存调用，尚未集成到SDK入口或手机。
