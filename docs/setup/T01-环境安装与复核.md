## 3. Android 配置与模板版本

实际 SDK 随附 ACE 模板中的 Android 配置为：AGP 7.4.1、Gradle wrapper 8.4、compile/target SDK 33、Build Tools 30.0.3。现有 Studio 的跨端模板则使用 AGP 9.1.1 / Gradle 9.4.0，仍引用 API 33 和旧 Build Tools 配置。因此同时准备 30.0.3 与 36.0.0；T06 创建工程后以真正生成的配置为准，不能混用两套模板的版本结论。

JDK 17 可供这两种 Gradle 版本使用；AGP 9.1 官方要求的最低 JDK 为 17、最低 Build Tools 为 36.0.0。[Gradle 兼容矩阵](https://docs.gradle.org/current/userguide/compatibility.html)、[AGP 9.1 配套说明](https://developer.android.com/build/releases/agp-9-1-0-release-notes)。这属于版本要求核对，未声称两套模板均已构建成功。

Google SDK Manager 完成了两版 Build Tools 安装和标准 SDK 许可确认。平台包下载中断、新 CLI 连接仓库失败后，使用 Google 官方仓库清单指定的 API 33 与 Platform Tools 归档补齐文件，核对发布方大小、SHA-1 及归档内容。随后旧 SDK Manager 能列出以下四项：


19.0 管理器读取较新缓存时有 SDK XML 版本提示，所需四个包的列表、文件和可执行检查均已通过。23.0 新 CLI 保留在独立目录，其远端包安装连接失败没有记为已修复；本轮构建工具基线使用固定版入口和已验证 SDK 文件。没有安装 Android Studio 桌面 IDE。[Google 命令行工具说明](https://developer.android.com/studio#command-line-tools-only)。

## 4. OHPM 启动问题的真实原因

首轮检查的 `.bat` 递归问题源于当前命令运行器未继承标准 Windows 变量 `OS`。系统机器级变量原本就是 `Windows_NT`；OHPM 根据它启用延迟变量展开，缺失时启动脚本发生递归错误。

在 Windows 进程内恢复该变量后，原始 `ohpm.bat --version` 返回 26.0.0.630。没有修补或替换 Studio 的启动脚本，也没有覆盖机器级 OS 变量。为当前命令运行器准备的环境激活脚本会按机器值补全该变量。
