## 已有真实边界

- T10 的共享页面为 `client/entry/src/main/ets/pages/Index.ets`，通过 `chatOwner.get()` 获取同一个 `ChatController`。
- `ChatController.setDraft(value)` 只更新可编辑文字；`send()` 才会校验当前文字与网关配置，并通过现有 `GatewayTransport.start(config, message)` 请求模型。不能在 ASR 完成回调中自动调用 `send()`。
- 现有 `snapshot()` 暴露 `draft/messages/busy/errorCode/requestId`，消息含 `id/role/text/phase`。控制器已经通过请求代次拒绝迟到模型结果，停止/后台由 `chatOwner.pause()` 调用 `stop('BACKGROUND')`。
- T10 当前是文本模型 turn，尚未接 Agent 工具循环、正式任务确认保存或 T11 持久会话。不能将 T15 接好解释为 T19 业务闭环完成。
- D 独立探测包已在 Pura 70 / API 26 安装并启动，原生 ASR 已有实时返回与用户录音可用反馈；TTS 实际声音/停止、离线及全项异常验收仍待补充。

## 候选最小接线（待 A/B 对齐）

| 触发 | 接入位置 | 必须保持的结果 |
| --- | --- | --- |
| 用户开始录音 | D 平台适配，由页面明确点击 | 按需请求麦克风；开始前生成本地语音代次，禁止并发录音/播报 |
| 用户结束录音 | 本次原生识别引擎的 finish | 只等待本次实际转写，不创建聊天消息或任务 |
| 本次最终转写有效 | D → A 的输入框 / `setDraft()` | 先核对语音代次、页面生命周期和输入修改代次；只写草稿 |
| 用户编辑文字 | A 现有输入框 | 递增本地输入修改代次，迟到 ASR 不覆盖用户编辑 |
| 用户点击发送 | A 现有 `send()` | 使用用户最终核对的文字和同一个 T10 网关入口；不另写 D 的 HTTP 请求 |
| 返回本次助手消息 | A/D 识别本次新增、完成的 assistant 消息 | 初次装配保留手动“播报”按钮；日后若做自动播报，需要用户主动启用，不能后台或订阅历史消息时自动发声 |
| 用户点停止播报 | D 实际 TTS stop/shutdown | 停止声音，同时保留聊天/任务结果；停止按钮与播报入口放在同一区域 |
| 离页、切后台、重录或取消 | A/D 生命周期统一装配 | 作废语音代次并停止原生资源；不回滚已经完成的任务保存 |

输入修改代次是待协商的本地状态，T10 当前没有对外暴露该字段。不得擅自添加到 `/api/model/turn` 请求体或将网关 requestId 当作语音取消凭证。`busy` 期间的录音/发送互斥和草稿保留行为由 A/D 一起确定。

## 原生路径与平台差异

Core Speech Kit 已使用 `online:1`、中文引擎直接采集麦克风；请求 PCM/16kHz/16bit/单声道、最长 30 秒。没有录音文件保存或上传代码，实际离线能力仍待用户方便时断网验证。不要为了适配旧草案强行保存音频或新增云 ASR/TTS 网关。

当前 `HarmonySpeechPort.ets` 位于独立 `probes/harmony-speech/`，不是正式共享模块。其受控导出按本机 schema 设置 `buildOption.ignoreCrossPlatform=true`，原生适配校验 OpenHarmony；见[边界决策](../decisions/D-T09-native-probe.md)。A 必须核对正式共享装配及非鸿蒙构建/加载行为，不能将探测配置直接复制进生产工程后声称 Android/iOS 支持。
