## 2. 提取的字段与规则（对齐 T03 第 2～5 节）

草案结构（`draft`）：

```json
{
  "schemaVersion": 1,
  "kind": "notice_draft",
  "notice": { "rawText": "...", "sourceLabel": "...|null", "publishedAt": "...|null", "timezone": "Asia/Shanghai" },
  "task": {
    "title": "...", "course": "...|null", "kind": "assignment|report|registration|other|null",
    "deadlinePrecision": "exact|date_only|unknown", "deadlineDate": "YYYY-MM-DD|null",
    "dueAt": "ISO8601|null", "timezone": "Asia/Shanghai",
    "priority": null, "submissionChannel": "...|null", "remainingMinutes": null
  },
  "checklistItems": [ { "label": "...", "state": "pending" } ],
  "missingFields": ["deadline"],
  "clarification": [ { "field": "deadline", "question": "..." } ]
}
```

规则：

| 规则 | 实现 |
|---|---|
| 原文不被改写 | `notice.rawText` 恒等于请求 `rawText`，模型输出里的原文被忽略 |
| 发布时间/来源保留 | 显式入参 `publishedAt`/`sourceLabel` 优先；无入参时采用模型建议；否则 null。用 null 不写“未知”字样 |
| 不臆测用户确认字段 | `priority`、`remainingMinutes` 强制 null，只能由 T13/T16 的用户确认写入 |
| 截止精度三态互斥 | `_normalize_deadline` 保证 exact（dueAt）/ date_only（deadlineDate）/ unknown（两者皆空）互斥 |
| 拒绝虚构时刻 | 原文没有明确写出同一时刻、模型却补成 `23:59`/`00:00` 时降级为 date_only；原文真写了 `23:59` 则保留 exact（其他时钟线索如“答疑14:00”不再放行） |
| 相对日期不推算 | “周五/明天/下周”且无明确日期时保持 unknown，追问发布时间或直接选日期 |
| 缺项追问或标记未知 | 只有 `title`、`deadline` 触发追问；course/kind/submissionChannel 缺项标记 null（未知） |

## 3. 多轮补齐协议

端点无状态，客户端回传上一轮 `draft` 与**累计的**结构化 `answers`：

请求：

```json
{
  "rawText": "下周五前把实验报告交到学习通。",
  "publishedAt": null,
  "sourceLabel": null,
  "timezone": "Asia/Shanghai",
  "draft": { "..." },
  "answers": [
    { "field": "title", "value": "用户改过的标题" },
    { "field": "publishedAt", "value": "2026-11-02T10:00:00+08:00" },
    { "field": "deadline", "value": "2026-11-07" }
  ]
}
```

**累计 answers 协议（重要）**：模型每轮都会依据原文重新提取，可能再次输出原标题/原截止；为保证跨轮保留用户修改，客户端必须**每轮累计重传全部用户 answers**（不只本轮新增项）。规则：
- 重复字段取**最后一次出现的值**（数组按顺序处理，后者覆盖前者）。
- 显式清空某字段：`value` 用 `null` 或空字符串（对应字段置 null）。
- 只传本轮新增项会导致前几轮的用户修改被模型重新提取结果覆盖。

回答字段与取值：

| field | value | 效果 |
|---|---|---|
| title | 非空字符串 | 覆盖任务标题 |
| course | 字符串；空串视为“无课程” | 覆盖课程，空串转 null |
| kind | assignment/report/registration/other | 合法枚举才写入，否则 null |
| deadline | `YYYY-MM-DD`（date_only）或带偏移 ISO 8601（exact） | 覆盖截止；用户显式选择的时间按原样保留（含 23:59） |
| publishedAt | 带偏移 ISO 8601 | 覆盖发布时间 |
| sourceLabel | 字符串 | 覆盖来源标签 |
| submissionChannel | 字符串 | 覆盖提交渠道 |

返回：

```json
{
  "type": "draft",
  "draft": { "..." },
  "degraded": false,
  "requestId": "…",
  "elapsedMs": 123
}
```

`missingFields` 为空表示字段齐备，可进入 T13 确认；非空表示仍需追问。`degraded=true` 表示模型输出无法解析为 JSON、已回退为“人工录入”草案（保留原文、全部未知并追问），客户端应提供人工录入入口。

## 4. 错误与边界

- 复用 T07 的统一错误协议与错误码；新增端点共享 `_gateway_guard`（配置、凭证、限流）与 `_post_upstream`（网络/非 200/非 JSON 统一映射为 `MODEL_ERROR`）。
- `rawText` 为空或超过 10000 字符、`publishedAt`/`timezone` 非法 → `INVALID_REQUEST` 400；`answers` 中 `kind` 取值非字符串/null → `INVALID_REQUEST` 400。
- 模型字段类型非法（如 `kind` 为数组/对象）→ 安全降级为 null，不抛 TypeError、不返回裸 500。
- 模型返回文本但解析失败 → 结构修复一次（`parse_model_json` 剥代码块/夹带文字取首个 JSON 对象）；仍失败返回 `degraded` 草案，不返回裸 502 冒充模型成功。
- 本端点不实现 history/messages 入参（会话历史重放仍归后续任务，见 session-message-contract 第 4 节）；多轮状态由客户端携带 `draft`+`answers`，服务端确定性合并。
- 上一轮 `draft` 只应**原样回传本端点此前返回的合法草案**，全部用户编辑经累计 `answers` 表达；`draft` 容器类型错误（`notice`/`task`/`checklistItems` 类型不对）时按“无上一轮”重新提取，字段值非法则按第 2 节规则规范化（截止→unknown、非法 kind→null 等），均不返回裸 500。手工构造的 `draft` 属未支持范围，不承诺全量字段校验、ID/版本/来源实体存在性或 LocalStore 规则。`answers` 中非对象条目被忽略。

真实调用暴露并修正一处规则：初版把“原文写了 `23:59`”也当作虚构时刻降级成 date_only，丢失了明确截止。修正后 `_is_fabricated_time` 只把「原文没有明确写出同一时刻 + 模型补成 23:59/00:00」判为虚构；原文明确写了 `23:59` 时保留 exact，其他时钟线索（如“答疑14:00”）不放行虚构时刻。用户 `answers` 里的显式时间一律按原样保留，不做降级。
