## 交给 A/B 的输入与编辑约束

1. 正式页面中由一个 owner 统一持有聊天/Agent 与语音状态、页面订阅；T10 的单 listener 不能同时被页面和另一个协调器覆盖。非鸿蒙平台保留文本主流程，语音能力需由 A 的平台装配明确返回。
2. ASR 完成只填写当前输入框；用户核对、编辑后再发送。点击发送才调用共用业务入口，不能根据“确认”“保存”等识别文字直接写任务。
3. T12 的上一轮 `draft` 原样回传，用户编辑经累计 `answers` 表达。每轮包含此前全部回答；同字段最后一个值生效，显式清空使用端点支持的 null/空串，不能仅上传本轮变化后丢掉旧修改。
4. 卡片分别暂存日期与时刻，未填完整不拼接假时间；`date_only` 不补 23:59，`unknown` 不生成精确截止。相对日期缺可靠锚点时追问或由用户选择。
5. 取消作废当前请求/卡片代次并保留可恢复原文，不提交；迟到响应不得恢复已取消卡片或覆盖新输入。修改方案后旧确认事件必须失效，使用 T16/T17 最终约定的版本校验。
6. 点击确认后显示保存中，读取实际提交回执和真实任务再显示成功；失败保留待确认内容。重试沿用同一操作凭证，冲突需回读并重新展示确认，不能盲目重试旧方案。

上述事件名称是交互描述，不定义新的网络字段；正式接口以 T13/T16/T17 的实现及评审为准。

## 状态与可说的话

| 实际结果 | 页面 / 手动播报可表达 | 必须等到的证据 |
| --- | --- | --- |
| 转写完成 | “转写已显示，请核对后发送” | 当前语音代次有效，输入未被较新编辑覆盖 |
| 提取/澄清返回 | “这是待确认草案”或具体缺项问题 | 当前请求的合法 T12 响应；不是保存成功 |
| 用户取消 | “本次未保存，原文保留” | 当前方案未提交；若已提交须按回执表达 |
| 保存中 | “正在保存” | 客户端明确确认事件已发出 |
| 保存成功 | “已保存，可在任务列表查看” | 实际成功回执和回读任务，不能仅凭模型回答 |
| 保存失败 / 冲突 | “未完成保存，可重试” / “内容有变化，请重新核对” | T16/T17 返回的真实状态；已成功业务与会话失败分开表达 |
