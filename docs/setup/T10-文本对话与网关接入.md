## 2. 网关配置与协议范围

打开应用的“网关设置”，填写：

1. **网关根地址**，如 `https://gateway.example.com` 或可信局域网调试地址 `http://192.168.1.20:8000`。可带反向代理前缀；末尾不要填写 `/api/model/turn`。客户端自动追加该路径。拒绝非 HTTP(S)、URL 用户信息、查询串与片段。
2. **项目凭证**：对应服务端 `GATEWAY_TOKEN`，非空 ASCII 且不含空白。密码输入框显示；不放入源码、日志、安装包配置或仓库文件。服务商 API Key 仅由 B 在服务端私有环境配置。
3. **最长等待**：5～120 秒整数，默认 45 秒。连接最多 10 秒，并有独立总等待时限；不会自动重复调用模型。

配置只驻留本次进程内存，不写入本地文件。当前会话也是内存状态；关闭/重启后设置与消息不会恢复，页面已说明。持久历史属于 T11，不能把本次内存列表当作该任务完成。

请求与 [T07 网关约定](T07-B最小模型网关与接口约定.md) 一致：

```json
{
  "message": "用户当前输入",
  "context": { "timezone": "Asia/Shanghai" },
  "tools": [],
  "results": []
}
```

通过 `POST /api/model/turn` 发送，头为 `Authorization: Bearer <项目凭证>` 与 JSON 内容类型。支持 `answer.text`；也按约定预留 `clarification.question` 的展示。非 2xx、HTTP 200 的 `type:error`、无效 JSON、空文本/错误类型均进入失败反馈；只显示受控错误说明及格式正确的请求编号，不回显服务端任意错误正文。

**当前每次提问独立处理。** T07 没有专用 `history/messages` 入参，页面显示先前消息不意味着模型收到了这些消息。`tools/results` 均为空；收到 `tool_calls` 会提示当前任务操作未接入，不执行工具、不写任务、不展示虚假成功。连续上下文、结构化工具消息和 T08/T11 会话接口需 A/B/C 后续对齐。

## 3. 请求与页面行为

- 发送时展示等待状态；同一时刻只允许一个请求，设置也暂不可改。输入上限为 4000 个客户端字符；允许请求期间继续编辑输入。
- 成功才追加助手消息，且只清除仍与发送时完全相同的草稿。期间新写的内容保留。
- 网络、超时、鉴权、限流、服务配置和模型失败都保留输入。未编辑的失败问题可手动重试，复用同一条用户消息；编辑后发送会成为新问题。
- “停止等待”、页面隐藏、Ability 进入后台均使当前请求失效并释放 HTTP 句柄；晚到的成功或失败不能覆盖新请求。停止本机等待不保证云端已中止计算；重试由用户明确触发。
- 默认不执行 health 自动探测或启动时请求，填写配置不会产生模型调用。`/health` 仅是网关存活检查，也不能证明真实模型已通。
