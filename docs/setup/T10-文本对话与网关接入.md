## 2. 网关配置与协议范围

打开应用的“网关设置”，填写：

1. **网关根地址**，如 `https://gateway.example.com` 或可信局域网调试地址 `http://192.168.1.20:8000`。可带反向代理前缀；末尾不要填写 `/api/model/turn`。客户端自动追加该路径。拒绝非 HTTP(S)、URL 用户信息、查询串与片段。
2. **项目凭证**：对应服务端 `GATEWAY_TOKEN`，非空 ASCII 且不含空白。密码输入框显示；不放入源码、日志、安装包配置或仓库文件。服务商 API Key 仅由 B 在服务端私有环境配置。
3. **最长等待**：5～120 秒整数，默认 45 秒。连接最多 10 秒，并有独立总等待时限；不会自动重复调用模型。

配置只驻留本次进程内存，不写入本地文件。当前会话也是内存状态；关闭/重启后设置与消息不会恢复，页面已说明。持久历史属于 T11，不能把本次内存列表当作该任务完成。

请求与 [T07 网关约定](T07-B最小模型网关与接口约定.md) 一致：

```json
{
  "message": "用户当前输入",
  "context": { "timezone": "Asia/Shanghai" },
  "tools": [],
  "results": []
}
```

通过 `POST /api/model/turn` 发送，头为 `Authorization: Bearer <项目凭证>` 与 JSON 内容类型。支持 `answer.text`；也按约定预留 `clarification.question` 的展示。非 2xx、HTTP 200 的 `type:error`、无效 JSON、空文本/错误类型均进入失败反馈；只显示受控错误说明及格式正确的请求编号，不回显服务端任意错误正文。

**当前每次提问独立处理。** T07 没有专用 `history/messages` 入参，页面显示先前消息不意味着模型收到了这些消息。`tools/results` 均为空；收到 `tool_calls` 会提示当前任务操作未接入，不执行工具、不写任务、不展示虚假成功。连续上下文、结构化工具消息和 T08/T11 会话接口需 A/B/C 后续对齐。

## 3. 请求与页面行为

- 发送时展示等待状态；同一时刻只允许一个请求，设置也暂不可改。输入上限为 4000 个客户端字符；允许请求期间继续编辑输入。
- 成功才追加助手消息，且只清除仍与发送时完全相同的草稿。期间新写的内容保留。
- 网络、超时、鉴权、限流、服务配置和模型失败都保留输入。未编辑的失败问题可手动重试，复用同一条用户消息；编辑后发送会成为新问题。
- “停止等待”、页面隐藏、Ability 进入后台均使当前请求失效并释放 HTTP 句柄；晚到的成功或失败不能覆盖新请求。停止本机等待不保证云端已中止计算；重试由用户明确触发。
- 默认不执行 health 自动探测或启动时请求，填写配置不会产生模型调用。`/health` 仅是网关存活检查，也不能证明真实模型已通。

## 4. 可复核的构建与检查

在配置好现有工具链的 PowerShell 中运行；本工作区先执行仓库外 `toolchains/Activate.ps1`，其他电脑按 [T01](T01-环境安装与复核.md) 设置对应路径。

```powershell
# 仓库根目录：严格检查与故障状态检查
node scripts/test-chat.cjs

# client/：鸿蒙 HAP；未配置个人签名时生成未签名包
devecocli build --modules entry@default

# client/：首次引入 HTTP 模块建议清理共享编译缓存后完整 ACE 构建
devecocli build clean
ace build apk --debug --target-platform arm64
```

测试脚本使用 `DEVECO_CLI_STUDIO_PATH` 下的 TypeScript；也可显式设置 `TYPESCRIPT_PATH` 指向已安装的 TypeScript 包。它检查 3 个共享核心 TS 文件，并运行 29 项协议、状态与模拟原生 HTTP 边界检查：坏响应/错误码、配置校验、重复发送、草稿保护、重试、总超时、后台/停止与迟到响应隔离、同步/异步异常释放资源。它不启动真实网关、不连接手机、不调用模型。

## 6. Android 真机客户端验证（人工服务，非模型）

设备为一加 Ace 3 / PJE110，Android 16 / API 36，arm64。首版 `5428894` 先确认中文示例输入和人工回复；发现键盘展开时页面偏移与空白问题后，采用上述 ArkUI RESIZE + 宿主 adjustNothing。最终 APK 逐项核对发送、错误和生命周期行为，实际受测包 SHA-256 与本节产物表一致。

| 场景 | 实际结果 |
|---|---|
| 界面/键盘/文字 | 配置页可输入并遮盖凭证；修正后标题、输入和发送按钮同时可见，键盘展开可发送；中文/emoji 人工回复显示正常 |
| HTTP 与错误 | 真机经过 USB 回环映射完成 HTTP；401、429、502 均显示约定反馈并保留输入；502 后手动重试成功，没有重复用户气泡 |
| 超时/停止/后台 | 配置 5 秒、人工服务延迟 8 秒时超时；主动停止及切后台后保留输入，等待服务实际返回后未出现迟到气泡 |
| 地址不可达 | 撤销本轮 USB 映射后显示网络错误，输入保留；这是不可达地址验证，没有关闭手机网络，不能当作飞行模式测试 |
| 长回复/编辑 | 12 段人工长文可上下滚动，输入区固定；请求期间改写的 `UNSENT DRAFT` 在成功响应后保留 |
| 关闭/重启 | force-stop 后确认无进程，再冷启动：配置和消息均重置，符合当前内存限制，不是 T11 恢复通过 |
