# B-模型Agent准备笔记
## 一、模型选型调研
### 1. 备选模型
1. **通义千问（Qwen）**
- 接口稳定，支持JSON结构化输出，适合Agent任务解析；国内可访问，成本友好。
2. **GPT系列**
- 指令跟随强，结构化能力好，但网络和费用受限，备选。
3. **DeepSeek**
- 推理能力不错，支持长上下文，适合复杂逻辑判断。

### 2. 选型结论
优先选用 **通义千问**，作为本项目的LLM基座，用于通知解析、任务提取、时间推理。

## 二、三个业务流程（Agent工作流）
1. **通知解析流程（输入：校园通知文本）**
    输入一段通知，Agent识别标题、截止时间、地点、参与对象、事项描述，输出标准化Task数据结构。
2. **任务更新流程**
    用户修改任务信息，Agent校验时间合法性、补充备注、提醒冲突。
3. **DDL提醒与规划流程**
    根据所有任务的截止时间，生成优先级排序，给出简易学习/行动规划建议。

## 三、风险与异常处理
1. 文本模糊、缺少时间：Agent主动输出缺失字段标记，交由用户补全。
2. 时间歧义（下周一、后天）：优先按自然语言时间解析，无法识别则标记为待确认。
3. 格式错乱：强制要求模型返回JSON，增加重试机制。

## 四、数据契约（初步）
Task字段：
- title：任务标题
- content：详情描述
- deadline：截止时间（ISO时间字符串）
- location：地点
- target：面向人群
- priority：优先级 高/中/低
- status：未开始/进行中/已完成

## 五、Agent限制与边界
- 只做通知理解、任务提取、时间推理、优先级建议
- 不自主联网搜索外部信息，仅基于输入文本做理解
- 不修改数据库，只输出结构化内容，交由后端服务保存

## 六、架构对接
前端：用户输入通知文本 → 传给后端
后端：调用Agent服务，拿到结构化task → 入库、推送提醒
Agent职责：自然语言→结构化数据转换，附带简单推理
