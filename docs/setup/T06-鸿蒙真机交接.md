## 5. 签名、安装与运行

### 使用 DevEco Studio 操作

1. 用支持数据传输的 USB 线连接手机。按手机系统引导开启开发者选项和 USB 调试，在手机上允许电脑调试。确认 Studio 设备列表中出现真实设备。
2. 完成前述系统/API 与工程 compatible 核对。
3. 在 Studio 的项目结构中进入项目签名配置。官方入口为 `File → Project Structure → Project → Signing Configs`（不同版本名称可能略有差异），使用有权限的本人或团队开发者账号登录，配置 **HarmonyOS 调试自动签名**，等待实际完成。具体以 [官方自动签名指南](https://developer.huawei.com/consumer/cn/doc/doccenter-deveco-studio/ide-signing-auto) 为准。
4. 选择 `entry` 和实际手机，运行 `Run 'entry'`。Studio 应完成构建、签名、安装和启动；分别记录结果。
5. 手机实际显示 **Hello World** 后保存截图。将本应用从最近任务中关闭，重新从桌面图标打开，确认仍显示 Hello World，记录有无闪退或黑屏。

自动签名必须针对当前包名 `com.campusddl.agent` 和实际手机生效。A 已有的 `entry-default-unsigned.hap` 是未签名构建结果，不能直接当作可安装调试包发送给手机使用。

### 已有 DevEco CLI 时的命令

先按你自己的安装目录配置 Studio 与工具路径；在 `client/` 目录运行。单台连接设备时：

```powershell
devecocli device list
devecocli device view --format json
devecocli auth login
devecocli signature generate --product default
devecocli build --modules entry@default
devecocli run --module entry
```

`auth login` 由你本人在官方页面完成。多台设备连接时，按 `device view` / `run` 帮助显式选择实际设备，避免安装到模拟器。

截图与本应用日志可用：

```powershell
# 先创建本机证据目录；截图时保持本应用在前台
New-Item -ItemType Directory -Path ./t06-evidence -Force
devecocli ui screenshot --path ./t06-evidence/harmony-template.png
devecocli log --bundle-name com.campusddl.agent --from 5m --tail 200
```

证据目录放在本机并单独回传，不把包含个人标识的原始输出直接提交公开仓库。命令行只是已有工具时的路径；没装 CLI 也可按上面的 Studio 操作完成。

## 6. 遇到问题怎么反馈

| 阶段 | 先核对并回传 |
|---|---|
| 找不到设备 | 手机系统、数据线、USB 调试授权、Studio 设备列表；可用设备列表的 Troubleshoot Device Connections |
| 版本/API 不兼容 | 手机真实 API、工程 compatible、电脑 SDK 版本、完整错误原文 |
| OHPM 启动失败 | Node/OHPM/Studio 实际路径及完整错误。若是已知递归错误，确认 Windows 进程 `OS=Windows_NT`，不修改厂商 bat；原因见 T01 |
| 同步或编译失败 | 构建日志中的第一个错误及上下文、插件/SDK 版本；只截最后一句 Build Failed 不够定位 |
| 签名失败 | 签名步骤、错误码、账号是否具备开发权限、设备是否被注册；不用发送登录凭据 |
| 安装失败 | 安装错误原文、系统/API、包名、是否生成签名 HAP |
| 黑屏或闪退 | 启动日志、本应用崩溃信息、截图/录像及操作步骤 |

签名额度、权限或现有应用冲突时，先保留错误并反馈；不要擅自删除团队云端证书或卸载已有应用来“修复”。
