## 设备场景与操作

设备上五种受控场景与独立的失败后取消分支均已执行通过：共19个界面检查点，包含4次真正进程重启（核对旧进程消失、新进程不同）。19不是19个独立故障类型，也不与188项主机/导出检查混计。应用内部读取并断言的是各隔离合成目录的真实快照；外部仅读取本包可见结果。

| 场景/入口 | 实际核对通过的行为 |
| --- | --- |
| 模拟保存失败 | 真正文件API用不存在源替换主文件失败；只有pending，导入任务/来源/材料/回执为0 |
| 同实例失败/原请求重试 | 比较失败候选中的operationId与最终回执；唯一方案/任务/材料/回执，不新建操作 |
| 暂存替换应答丢失 | 替换成功后受控抛错；唯一pending在重启后只读恢复，需要再明确确认 |
| 提交替换应答丢失 | T16读回实际回执识别已保存；冷读不重复创建或写主文件 |
| 独立版本变化 | 另加隔离合成任务后，旧方案确认VERSION_CONFLICT且主文件字节不变；取消保留独立任务 |
| 失败后取消分支 | 明确取消只改变方案终态，不创建导入业务实体；新确认实例读取消结果不复活 |

4次真正重启分别位于保存失败、暂存应答丢失、提交应答丢失和版本冲突之后；每次重启后先走只读恢复，没有自动确认。设备末尾回到原正式通知页，升级前、升级后、隔离诊断完成后的旧任务标题/截止/三材料与来源逐项相同。没有直接读取生产业务主文件，因此旧任务对照不扩大为全量生产字节审计。

本轮未配置应用网关、未启动模型服务、未录音/播报；最终确认电脑8000无监听、本次没有USB8000映射，应用仍提示网关未配置，没有新增运行凭证。合成诊断目录保留供复查，最后索引指向已取消的测试终态，没有自动删除恢复痕迹。
