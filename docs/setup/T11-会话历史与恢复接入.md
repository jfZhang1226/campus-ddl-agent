## 1. 实际聊天接入

- `EntryAbility` 用应用私有目录初始化唯一 `chatOwner`，复用 `ClientStorage` 的队列和会话存储。页面重新进入复用同一控制器；销毁后新实例从文件读取。
- 首次启动读取最近**修改**的合法会话；不是最近浏览的会话。没有历史时保持空白，首次发送才创建会话文件。读取期间禁止发送，保留期间新输入的文字。
- 发送前保存用户消息及 `pending`，成功后才请求网关。回答/追问保存成功后才清空原输入；等待期间用户编辑的新输入保留。
- 保存失败保留输入和内存回复、显示存储错误，继续阻止发送；“重试保存对话”仅重试本地写入，不调用网关。发送前失败且本地重试成功后，仍需用户明确发送。请求/读写进行中禁止切换；保存已失败且空闲时可只读浏览历史，离开未保存会话须明确确认，可取消保留内容，不依赖保存最终成功。
- 冷启动把已保存的 `pending` 显示为 `interrupted`；读取不改文件，不补造回答、不自动联网。最后一条未完成用户问题可回填输入，明确重试时复用其消息 ID。
- URL、项目凭证、超时设置、未发送输入仅在内存中；已发送且中断的问题属于消息历史。每次提问仍是 T10 单轮请求，不将历史或工具结果发给模型。

## 2. 页面接入接口

| 接口 | 行为 |
|---|---|
| `getClientStorage(filesDir).history.list()` | 返回 `StorageResult<SessionIndex>`；按 updatedAt 实际时刻倒序、同刻按 ID 排序；单份不可读文件列入 issues，不清空或掩盖 |
| `.history.get(id)` | 完整 `SessionDocument`，含结构化 calls/results、扩展字段；读取不写盘 |
| `chatOwner.get(filesDir)` | 首次初始化并开始读取；后续可无参复用，运行中拒绝切换目录 |
| `controller.initializeHistory()` | 可重复调用；读取未成功时提供明确重试，不发请求 |
| `controller.openHistory(id, discardDraft=false, discardSaveToken='')` | 加载指定会话；非空输入需确认，保存失败时另需对应当前 navigationToken 的明确放弃确认；目标读失败保留原内存输入/回复与本地保存重试能力 |
| `controller.newConversation(discardDraft=false, discardSaveToken='')` | 新空会话，仅首次发送落盘；失败保存须同样确认放弃，原磁盘主文件/备份/tmp保留 |
| `controller.retryHistorySave()` | 明确重试本地保存；成功前保留所有输入与回复 |
| `repository.newDocument(title)` / `.save(candidate, expectedRevision)` | 底层完整候选与比较保存；newDocument 本身未落盘，不作为模型工具 |

页面通过 `subscribe/snapshot` 的 `historyReady/historyLoading/savePending` 禁止未读完时发送、保存未定时切换；`canAbandonSave` 仅在保存已失败且无请求/读写在途时为真，此时可只读浏览或请求明确放弃确认。`navigationToken` 绑定当前输入、会话/请求和保存尝试，重试或输入变化后旧确认失效；它只在内存使用，不是持久operationId或业务提交授权。展示 `storageErrorCode/storageNotice`，不要把网关错误当作存储重试。正式详情使用 `.history.get(id)` 展示完整结构化内容，只显示磁盘版本，未保存的回复仍在当前对话。原工具记录只读保留，不因进入历史页执行调用或确认方案。

实现入口：[SessionRepository](../../client/entry/src/main/ets/data/SessionRepository.ts)、[StoredChatHistory](../../client/entry/src/main/ets/chat/StoredChatHistory.ts)、[ChatController](../../client/entry/src/main/ets/chat/ChatController.ts)、[应用所有者](../../client/entry/src/main/ets/chat/ChatOwner.ets)。

## 3. 保存、状态与兼容

仍使用 T08 的 `sessions/<id>.json`、schemaVersion=2、revision、临时文件/备份/最后替换和真实文件适配，没有引入第二份历史数据库。队列捕获候选，失败不会污染后续队列；版本冲突不会自动重读覆盖。相同内容不写入、不加版本。自动标题取第一条用户文字至多 60 个 UTF-16 单元，不截断代理对。

| 存储状态 | 读取界面含义 |
|---|---|
| pending | 上次未完成，显示 interrupted，磁盘状态保持 |
| completed / 旧 done | 完成 |
| failed / stopped / interrupted | 失败、停止或中断，用户明确决定是否重新请求 |

消息的完成只表示该聊天回合状态，不代表任务实际提交成功。新消息分别保留 text/answer/clarification。原工具调用、结果、旧摘要、时间、ID、顺序及扩展 JSON 字段继续保留；不能删减旧消息或更换其身份。v1 读取只在内存转换，下一次明确保存才升级，备份保留上一份原始字节，详见[会话契约](../session-message-contract.md)。

T11 新写状态约定为 pending/completed/failed/stopped/interrupted，运行态 done 写为 completed；pending→interrupted 是只读显示投影，不改文件。存储层仍校验非空字符串，不收紧为封闭枚举，旧 done 和其他合法状态继续兼容，不能据此推断工具 results.success 或任务提交结果。恢复问题后明确发送仍只发当前一条；T17 的历史上下文、工具配对/重放另行定义，retryRow 不是未来 Agent 重放协议。

客户端 clarification 解码/存储/显示为前向兼容；当前 `/api/model/turn` 没有独立 clarification 返回分支，T12 的 `/api/agent/extract-notice` 返回 draft，不能混同。主机与双端人工 HTTP 覆盖不等于真实生产网关或真实模型已返回该类型。

错误按 `success/data/errorCode/message` 返回：非法候选为 INVALID_ARGUMENT；版本变化为 VERSION_CONFLICT；真实 I/O 失败为 STORAGE_FAILED；损坏、未知版本和恢复痕迹保持 CORRUPT_DATA/UNSUPPORTED_SCHEMA/RECOVERY_REQUIRED。全部保留原文件，不静默重置。只有临时文件、没有主文件或备份的首次写入失败不能自动提升临时文件；完整恢复交互和会话删除/方案清理留 T30。会话和业务快照不是跨文件事务。
